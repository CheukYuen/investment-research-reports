**证据一 · API 结构性缺陷**：`search_knowledge` 无 `limit` 参数、无可用分页（`next_cursor` 恒为 `undefined`）、无日期范围。它是**全库相关性 top-N 检索**（实测 "数据中心" 恰好返回 100 条 = 硬顶截断；"GPU" 42、"半导体设备" 58），今日新报告与全部历史抢排名，宽词基本抢不过。

> **复核修正（采纳外部评审，2026-07-14）**：原文"更多主题词无法修复"**过绝对**。实测补证：**窄而高特异度的词能定点补洞**——`AI PCB`→补回 2 份 PCB 报告、`英伟达`→补回 P0 英伟达路演、`海光`（全库仅 3 条）→补回曙光8000、`台积电`→补回台积电。但**宽词仍被 top-100 截断**（`数据中心` 100 条里今日 0 份）。准确表述应为：**加窄词可局部补洞，但（a）需事先知道要搜哪个公司/词=循环依赖，（b）词表无限膨胀，（c）宽词受 top-N 截断——因此无法建立"系统性完整召回"保证**。这不推翻否决结论，只把理由从"加词无用"精确化为"加词无法保证完整性"。
